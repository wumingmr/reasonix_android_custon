# 草稿机制修复验证记录

本记录对应基于 `8e2e6ef0` 的本地修复。工作区同时包含此前草稿机制的改动；
本任务没有创建提交、PR、CI 运行或发布。[English](SESSION_DRAFT_REPAIR_VALIDATION.md)

## 六类问题的修复

| 问题 | 修复边界 | 回归依据 |
| --- | --- | --- |
| 重试只改显示设置 | 在运行时重建和执行准入屏障内配置或替换真实 Controller；准入再次核验身份和配置。候选失败保留原运行时及 Session。 | `draft_runtime_test.go`：真实权限变化、canonical 模型/effort/MCP 替换、失败候选不覆盖旧运行时。 |
| 捕获后仍能编辑 | 首个 await 前同步登记准备 ID 并锁定内容、设置；flush 核对捕获快照，Begin 核对摘要。 | 草稿所有权、保存竞态及 Composer 测试。 |
| 丢弃或迟到响应影响其他项目 | 捕获 DraftID、generation、编辑版本、revision 和导航意图；后端 CAS 删除。 | 确认期间切项目、迟到删除及导航隔离测试。 |
| 附件任务计数残留 | 全局任务结算与内容写回资格分离；字段更新合并到原草稿最新内容。 | 冲突替换后的任务结算测试；原生文件拖入经过 preload 并落盘。 |
| 重启丢失操作身份 | 只读状态包含原操作；显式继续携带操作版本，并无缝移交 worker 租约。 | 请求/继续 CAS、重启不重放、v3 冻结快照回归。 |
| 未知状态停止查询 | 应用级查询持续核实 shell 派发及未知接收；按操作版本拒绝倒退；取消返回 accepted 同样完成一次转换。 | 可控 Promise 的轮询/取消测试；shell 回执先落盘及去重测试。 |

同时修复了相邻边界：Begin 丢响应后以相同请求 ID 在后端串行核实；取消与
运行时发布、持久准入互斥；旧 worker 收尾期间的新操作不会静默卡住。正常退出
等待附件、提交准备、目标保存版本及恢复目标。测试清理等待 Controller 真正
关闭存储后，才删除临时目录。

## 验证范围

- 前端：应用生命周期、草稿所有权/保存竞态、Composer/剪贴板、远程、transcript、
  应用与测试类型检查、hooks、分层及生产构建。
- Go：Desktop 按独立模块测试；草稿 store 和运行时执行聚焦 race 检查；
  根模块测试覆盖共享 Controller/session 改动。
- Electron：219 项 shell 测试；隔离目录中的真实服务新建、原生 PNG 剪贴板保存及 Composer 键盘粘贴、
  原生文件拖入、附件重启恢复、编辑后立即正常关闭、SIGKILL 后服务重启恢复。
  测试不调用模型，剪贴板测试内容为临时 fixture。
- 浏览器：项目加号、顶部新建、快捷键、项目右键、命令面板均恢复同一草稿；
  20 次重复新建不增加正式会话行；30 次采样均从历史页出发，到正确草稿可编辑
  为止。最近一次 mock 浏览器 p95 为 **28.9ms**。
