# 桌面输入区控件

[English](COMPOSER_CONTROLS.md)

## 运行期间发送消息

Reasonix 工作期间仍可继续输入。加入队列的消息等待后续执行；选择**引导当前轮**，
则在当前轮下一个支持接收引导的边界生效，并非立即打断正在进行的模型请求。
如果当前轮在接收引导前结束，消息会留在收件队列中，供后续回合处理。

当前输入自动保存。提交被拒绝时保留文字，确认状态后自动恢复编辑。提交响应丢失时，
Reasonix 会核查已有提交，不会重复发送。仍无法确认时只显示一个**重试**入口，
用于重新核查恢复状态，不会重发消息；结果确认前继续保护输入。

输入区不再提供已保存版本／本窗口版本选择，也不再生成可恢复输入副本列表。
发生并发保存时自动刷新一次版本号，并保留当前文字。队列条目编辑仍保留独立的冲突处理。

## 控件

通过 **+** 菜单添加内容，或启用计划、目标模式。Reasonix 统一采用标准执行
行为，不再提供交付质量选择器或交付标签。权限仍由独立的“仅可查看／工作区内修改／完全权限”菜单控制。
模型和思维力度分别选择；模型不支持时隐藏思维力度入口。
底部信息栏不再重复显示模型名称，本轮费用保留两位小数，费用详情仍保留
原有精度。

已启动的目标可在 **+** 菜单中编辑，编辑不会替换目标身份或清零已接纳轮数；自动轮数上限
留空表示不限。自动目标轮执行期间仍可打开同一菜单并立即暂停。

圆环打开用量详情。**本轮耗时**扣除等待用户的时间，包括审批、回答和 MCP
交互，并在控制器记录的完成时间停止；重试时间仍计入本轮。等待、重试和
结束后保留本轮 token 与吞吐指标。流式传输中的 token 按字符密度估算，
不再统一按每 token 四个字符计：ASCII 约四个字符一 token，中日韩文字约
1.3 个字符一 token。圆环里的吞吐和 token 两行是本轮口径，统计本轮累计
输出，流式期间带估算标记；底部信息栏的吞吐是最近一次请求，其本轮 token
项是"输入加输出"的回合总量。**会话耗时**单独展示会话累计值。新一轮开始时
重置本轮指标；这些实时指标不是持久化历史报告。每个回合的完成指标只结算
一次，后续后台作业状态更新不会覆盖它们。

输入区默认高度为 140px，并保留手动调整的高度。运行时使用适配主题的
边框动画，减少动态效果设置下显示静态边框。输入框上方有一条状态条，说明
当前状态；本轮进行期间还会在右侧固定展示本轮耗时、tokens 累计与吞吐速度。
分组靠颜色和位置，不靠标点。耗时排在最前，先回答"是不是卡住了"；估算标记
只落在 tokens 上，因为耗时是精确值、吞吐由它推导。状态条变窄时先让出状态词
的宽度，绝不把某个读数从中间截断，并在低于阈值时整段去掉速率。吞吐只在
模型正在出字时出现，避免把被等待冻住的速率当成当前速度展示。该状态条的
实时区域仍然只播报稳定的状态文案。审批、回答和重试提示仍然可见。

底部信息栏将工作区和分支合并为一项：显示当前分支名，悬停提示同时展示
工作区路径和分支。非 Git 工作区显示工作区名称，旧配置列表自动去重。
旧配置如果只显示模型，迁移后仅保留工作区与分支。
首次升级默认使用图标版，后续手动选择的文字版或图标版会保留。旧版本
重写配置可能移除升级标记，再次升级时会重新应用图标版默认值。
